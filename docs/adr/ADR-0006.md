# ADR-0006: stdlib net/http over chi/gin

Context: Three different ways for realisation: framework/thin router/stdlib. YAGNI for template (no particullar realisation without needs, user can adapt router for their preferred HTTP router lib)

Decision: Go 1.22+ ServeMux, hand-wired middleware. Name of package: `httpserver`, to avoid shadowing net/http. Showing the `naked` middleware realisation on standard package, so it will be easily to migrate realisation (only for who familiar with net/http)

Consequences: No route groups or binding sugar and manual middleware chaining

At 10x scale: Move to chi, because of route-group count making hand-wired middleware assignment error-prone.

Status: Accepted
