# ADR-0005: Error mapping at the boundary

Context: Errors cross all three layers and leak of information at 5xx responses - security problem. Domain errors - boilerplate code (for example NotFound error will exist in every domain, which generates duplicate code per domain)

Decision: Shared errors in core/apperror. The adapters transform the drivers errors to *apperror*; ErrInternal: already-logged marker for boundary plumbing - domains never wrap it. Constraint violations pass through unmapped (defense-in-depth; verified by `TestConstraint` in `widget_integration_test.go`). `writeError` maps kinds - statuses, 5xx sends generic text and logs the real chain

Consequences: Every new kind needs a conscious mapping entry

At 10x scale: More errors - more mappings, when unique rule appears. ErrConflict becomes 409 when uniqueness appears (pg 23505); Structured ValidationError when clients need field-level errors

Status: Accepted
