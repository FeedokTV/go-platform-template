# ADR-0003: slog over zap/zerolog

Context: slog is already built with "ports and adapters" logic (Logger interface and Handler).  Libraries with concrete APIs causes the whole codebase edit when swapping the logger. Slog's Logger/Handler split makes it a one-line handler change (for example zapslog) 

Decision: stdlib with logger front-end and pass loggers in system parts; core services may receive the logger, domain types never log. SetDefault as the safety net that keeps third-party strays in our log format

Consequences: Marginally slower than zap - accepted

At 10x scale: swap the Handler (e.g. zapslog) if throughput demands - the Logger front-end and all call sites stay untouched

Status: Accepted
