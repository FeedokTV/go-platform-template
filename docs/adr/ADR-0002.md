# ADR-0002: pgx over GORM

Context: The naked SQL shows the queries, so the developer who uses template will easily can understand and migrate realisation on his own ORM or DB

Decision: Hand-written SQL queries with pgx/v5 + pgxpool. RETURNING for the DB-generated fields. Name of pgx packages is `postgresadapter` to avoid shadowing pgx and other `postgres` drivers

Consequences: Hand-written field scan may cause bugs for new realisations (a scan-order bug shipped and was caught only by the integration suite). Also the lint gap (rowserrcheck/sqlclosecheck don't cover pgx native - rows discipline is manual + integration-tested)

At 10x scale: sqlc/query-builders when query volume makes hand-scanning a tax.

Status: Accepted
