# ADR-0009: Example-domain conventions (Widget)

Context: conventions for the example domain, chosen for teachability

Decision:
- Int for ID: bigint identity over UUID, simpler, index-friendly; cost: enumerable, acceptable for templates
- Repository: accepts and returns Widget by value. Pointers would invite nil-checks in every method, heap escapes (GC pressure), and signatures that falsely advertise mutation; an ~80-byte copy costs nothing.
- ID, timestamps is on DB side, using the conveyor method (Name, Weight in, to DB, return ID, Name, Weight, CreatedAt, Updated at on out)
- `RETURNING` as correct read-back (no second fetch, unnecessary new query)
- Three layers validation: shape in the adapter (is it parseable?), invariants on the domain type (is this a legal Widget?), operation rules in the service (does this operation make sense now?)
- PUT, not PATCH: excessive logic for checking a specific field for changes in the template (update the whole model)
- LIST returns zero-slice not nil. Zero is also an answer, not error
- No trigger for UpdatedAt in DB. We want to see queries, not that complex realisations 

At 10x: triggers for rows (for example `updated_at` after updating Widget)

Status: Accepted
